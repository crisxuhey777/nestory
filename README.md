# Nestory · V3.0

**A little nest. A lifetime of stories.**
为每一个家庭，珍藏成长的每一天。

Nestory（Nest + Story）是一个高品质家庭成长记录 App：把喂养、睡眠、尿布、身高体重、照片与家人的共同记忆放在一个安静、克制的界面里。本仓库是 V3.0 品牌与 UI 商业化升级后的完整前端实现。

## 快速开始

```bash
npm install
python -m pip install PyMySQL     # 后端用 PyMySQL 连 MySQL
python backend/setup_mysql.py     # 首次：建库 nestory、账号、三张表
python backend/server.py          # 本地后端（另开终端），http://127.0.0.1:8000
npm run dev                       # http://localhost:5178
npm test                          # 业务规则单元测试（Vitest）
npm run build                     # tsc -b + vite build
```

Windows 下后端可以直接双击 `backend/start_server.bat` 启动，不必开命令行：它会先确保本地 MySQL
在 3306 监听，再启动服务，并打印当前模型（`provider` / `model` / 一行 `probe: ok`）和数据库 ping。
字段含义见 [backend/README.md](backend/README.md)。

> 开发服务器只监听 `localhost`（IPv6 回环）。若浏览器打不开，请使用 `http://localhost:5178` 而不是 `127.0.0.1`。

前端启动后先请求 `GET /api/auth/me`：没有登录就显示登录/注册页；登录成功后拿到的 `AppState`
来自 MySQL，**拿到数据才渲染**。注册时填的昵称、宝宝昵称和生日会写进 `users`，之后每次打开、
换浏览器只要登录就能取回，不用再填；页面上的每次改动会在 800ms 防抖后自动 `PUT /api/state`。
后端没启动会停在引导层，提示运行 `python backend/server.py` 并提供重试。Vite 已把 `/api` 代理到
`127.0.0.1:8000`，无需处理 CORS。

数据库连接默认 `nestory@127.0.0.1:3306/nestory`，可用 `backend/db.env` 覆盖（该文件已 gitignore）。
密码用 PBKDF2 存哈希，会话是 HttpOnly Cookie，库里只存令牌的 SHA-256。接口、表结构和边界见
**[backend/README.md](./backend/README.md)**。

后端日志同时打印到控制台和 `backend/logs/nestory.log`（按天切分、保留 14 天、每 2 秒落盘）。
每个请求带 8 位 `rid`，排查时用 `Select-String rid=xxxxxxxx` 就能串起账号、AI 与响应的全过程；
日志不含密码、Cookie 和 AppState 内容。

AI 目前有四处入口，都把当前整份 `AppState` POST 给后端：首页 hero 的「每日一句」每天让模型写一句，
生日/满月/百天/半岁/春节/中秋/母亲节等特殊日子会带一行小标签和对应的祝福（按天缓存，当天刷新不重复请求）；
首页「AI 小结」写一条小结并追加成 milestone、包回**同样结构的完整 AppState**；成长页「AI 成长分析」
给近 7 天的三条观察和两条建议；相册页「AI 相册故事」把照片标题与里程碑写成 2–3 句。免费模型
（默认 Pollinations，无需 Key）通常 3–40 秒，等待期间播放呼吸动画；公网失败时后端自动本地兜底，
页面都不会卡住。后端不在线时，hero 会退回 `src/data/config.js` 里的那句静态文案。

## 核心业务规则

这些规则是产品可信度的基础，均有测试覆盖：

1. **亲喂与奶量严格分开。** 亲喂记录左右侧秒数；瓶喂母乳记录 `bottleMl`；配方奶记录 `formulaMl`。亲喂分钟数**绝不**换算成毫升，统计中奶量只由两个毫升字段相加。
2. **喂养间隔 = 本次开始时间 − 上次开始时间。** 以开始时间而非结束时间为准，跨午夜、深夜补记都按真实时间计算；瓶喂与配方奶同样可以修改喂奶时间。
3. **真实日历月龄。** 使用 `addMonths` 的月末 clamp 计算，不按 30 天近似；例：7/31 出生，11/11 显示「3 个月 11 天 · 第 103 天」。
4. **修改或删除后立即重算。** 次数、奶量、平均间隔、近 7 天柱状图、首页摘要全部由当前记录派生，删除有二次确认并说明影响。
5. **提醒只是辅助。** 界面明确提示不替代宝宝的饥饿信号与医生建议；预测时间基于上一次喂养开始时间。

```

  App.tsx               StoreProvider + 路由外壳 + TabBar + Toasts
  brand/
    Logo.tsx            巢形标记 / 字标 / 横向锁定（与 public/brand 同一套几何）
    icons.tsx           38 枚实心双色图标 + <Icon />
  components/
    Common.tsx          ScreenHead / SectionHead / TabBar / Toasts / Sparkline
    Sheet.tsx           底部抽屉（portal、ESC、锁滚动）
    QuickSheets.tsx     睡眠 / 尿布 / 成长数据快捷记录
  data/
    config.js           产品配置（导航、枚举、默认值、限制、文案标签）
    config.d.ts         配置数据的类型声明
    types.ts            领域类型
    store.tsx           先取数再渲染的 store（reducer + toast + hydrate）
  lib/
    date.ts             月龄、时长、相对时间、纪念日
    stats.ts            喂奶间隔、今日统计、近 7 天、睡眠/尿布汇总
    prefs.ts            阅读偏好（字体大小、减少动效）与 CSS 变量
    route.ts            hash 路由
    viewer.ts           当前操作者显示名（viewerId → 家庭管理员 → 我）
  pages/                Home / Feed / Growth / Album / Profile / Settings / Reminders / About
  styles/
    tokens.css          颜色、字体、圆角、阴影
    base.css            重置、桌面居中画布、排版原子类
    app.css             导航、按钮、chip、抽屉、表单等基础组件
    pages.css           各页面版式
    fonts.css           自托管字体（212 个 @font-face 分片）
```

- **React 19 + TypeScript 5 + Vite 7**，无 UI 框架、无图标库、无 CSS 框架。
- 样式全部使用设计 Token；页面不写死颜色。
- 桌面端（≥720px）保持 460px 手机画布居中，带柔和的环境光背景，便于演示。

### 数据与配置分离

产品里「可调的结构与文案」集中在 `src/data/config.js`，页面只负责渲染与交互：

| 配置 | 内容 |
| --- | --- |
| `APP` | 名称、版本、年份、中英 tagline、默认记录人 |
| `STORAGE_KEYS` | 偏好与 IndexedDB 的存储键（业务状态存在 MySQL，不再写 localStorage） |
| `NAV_TABS` | 底部四个 Tab 的路由、文案与图标 |
| `QUICK_ACTIONS` | 首页四个快捷入口及其行为 |
| `HERO` | 照片上限、6 秒轮播、触摸暂停、文案 |
| `FEED_METHODS` / `FEED_PRESETS` / `FEED_DEFAULTS` | 三种喂养方式、奶量预设、默认奶量 |
| `REMINDER_INTERVALS` | 提醒间隔档位 |
| `FONT_OPTIONS` | 字号档位、缩放比例、样例字号 |
| `PERMISSIONS` | 三档家庭权限的名称与说明 |
| `MEDIA_LIMITS` / `MEDIA_GROUPS` | 图片与视频上限、相册六种添加入口 |
| `PROFILE_MENU` | 我的家庭设置列表 |
| `NOTIFICATION_LABELS` | 通知权限状态文案 |

改导航、改档位、改默认奶量、改相册入口，都只需改这一个文件；`config.d.ts` 提供与之一致的类型。业务判断（间隔计算、月份分组、权限保护）仍在 `src/lib` 与页面内，不混入数据文件。

### 真实配置与后端数据边界

`src/data/config.js` 只放**前端自己的产品配置**：导航、业务枚举、文案标签、默认值、媒体上限、路由与 API 路径。它不包含宝宝、家人、照片、喂养、睡眠、成长等任何业务记录。

所有业务数据只有一个来源：登录之后 `GET /api/auth/me` 返回的、存在 MySQL 里的 `AppState`。`backend/fixtures.py` 只负责新账号的初始示例数据；前端不保留 `test_config.js` / `seed.ts`，也不做「先显示本地示例、再用接口覆盖」的闪屏。未登录时显示登录/注册页，后端未启动时停在引导层，都不会显示假数据。

要换新账号的初始示例，改 `backend/fixtures.py`；要迁移到别的数据库，改 `backend/db.py` 与 `backend/accounts.py`，前端与业务逻辑无需改动。

## 设计取舍

- **首页先讲品牌，再讲数据。** 首屏是大幅宝宝照片、名字、月龄与一句成长文案；照片下方是一排悬浮快捷圆钮（喂奶、睡眠、尿布、成长数据），随后才是六项今日摘要与其余分区。
- **四个快捷圆钮与记录按钮不随屏幕高度消失。** 主视觉高度用 `clamp(340px, 52dvh, 500px)` 收放，快捷区做成压在照片下沿的独立圆角卡片，四个圆钮与「记录这次喂养」合并为同一块；从 320×568 到 430×932 的首屏都能完整看到，不再被底部 TabBar 盖住。
- **相册保留「每月列表」的编辑节奏。** 封面承担最近一张的视觉焦点；进入月份后，每月第一张仍可全宽，其余回到双列，避免照片墙变成等大的格子。
- **喂养页顶部改为一行上下文条。** 原来的大号统计与下方统计条重复；现在只保留「今天已喂养 N 次 · 瓶喂 X ml / 最近一次」，把视觉重心让给计时器与保存。
- **喂养方式默认不预选。** 进入页面时三种方式均为空，必须由用户明确选择；再点一次即取消。只有主动选亲喂并开始计时才会走计时流程，选瓶喂不会再意外触发亲喂计时。
- **按钮反馈是「压下去、弹回来」，不是装饰性闪烁。** 所有按钮在 pointerdown 时缩到 96.5%，松手用带回弹的曲线回到 100%，有底色的主按钮再散开一圈很淡的香槟描边；拖动超过 10px 或系统开启减少动态效果时不播放，避免干扰滚动与晕动敏感用户。
- **返回上一级有方向感。** 点返回时新页面从左侧 18px 处滑回并淡入（280ms），旧页面已被路由替换；底部 TabBar 保持贴底不参与位移。只对返回生效，Tab 切换与向前进入仍是瞬切，避免每次切页都拖慢节奏。
- **首页两个喂奶入口有明确分工。** 摘要卡里的「记录这次喂养」进入快速记录：一张表单 + 最近 5 条，保存后直接回首页；下方快捷圆钮「喂奶」进入喂养中心：统计、趋势、提醒与完整记录，不再显示录入表单。两者不再落到同一个界面。四个快捷圆钮使用同一颜色，不额外强调其中一项。
- **喂养记录是二级界面。** 主页面只保留最近 3 条作为上下文，点「查看全部 N 条记录」进入全屏列表；编辑、删除、分组与主页面一致，返回后回到喂养页。
- **首页主视觉只从相册取图。** 设置照片的选择页只列成长相册已有内容，不再提供第二个上传通道；要换新照片先去相册添加，避免同一张照片存两份。
- **睡眠记录不再依赖计时器。** 打开快捷「睡眠」，开始与结束各填日期 + 时间；跨夜时把结束日期选为次日即可。结束早于开始、单次超过 24 小时、或时间晚于现在都会被拦下；已有未结束的睡眠会转为「补充结束时间」。
- **图标为实心双色。** 以形状而非线条表达，主色森林绿，香槟金只做一处强调；不使用 Lucide / SVG 线稿 / Emoji。
- **数字使用衬线体。** 喂养次数、奶量、体重、计时器使用 Fraunces，让「记录」有仪式感；正文保持 Inter + Noto Sans SC 的高可读性。
- **顶级 Tab 页面不放返回箭头。** 成长记录与成长相册由底部 Tab 进入，标题改为左对齐的品牌式页头（英文眉标 + 衬线标题 + 一句上下文），右侧只保留「新增」；返回箭头只出现在喂养、提醒、设置等二级页。
- **返回路径按来源决定，而不是固定跳一个页面。** 快速记录与喂养中心返回首页；设置、关于返回我的家庭；提醒中心由首页或设置进入时携带 `from`，返回对应入口，避免从首页点进来却回到「我的」。
- **成长页先给一个「最新测量」焦点。** 把原来三张等权重的数字卡合并成一张深绿测量卡（体重为主、身长/头围为辅），趋势与队列表格依次退后，页面有了主次而不是仪表盘。
- **相册先给一张封面。** 最近一张照片升为 4:3 封面，月份筛选放到封面之后；同一张照片不再在网格里重复出现，每月剩余照片回到双列。
- **全屏查看可左右切换。** 点开任意照片后，在当前筛选结果里左右滑动（或点两侧箭头 / 方向键）切换，底部显示 `2 / 6`；首尾循环，视频同样可以切到，Esc 或点空白关闭。
- **Live 与视频用「封面 + 徽标」表达。** Live 在封面和全屏里循环播放并静音，视频使用系统播放控件；两者都以静帧海报进入网格，避免相册变成会自己动的广告牌。
- **视频不进 localStorage。** 上传的视频与 Live 短片写入 IndexedDB，状态里只保存海报与 `videoId`；否则一段 3 秒短片就会撑爆 5 MB 的本地存储。
- **字体大小通过 `--type-scale` 放大文字，而不是缩放画布。** 直接 `zoom` 会让固定底栏错位、内容右侧被裁；现在所有字号写成 `calc(Npx * var(--type-scale, 1))`，布局宽度不变，只让阅读更松弛。

## 未完成事项

1. **原生能力未接。** 仓库保留了产品结构，但尚未加入 Capacitor 工程、系统通知、震动与相册写入权限。
2. **还没有云同步。** 注册、登录与数据持久化已经接通，但 MySQL 跑在本机，数据只在这台电脑上；换设备同时使用、家庭成员共享同一份记录、公网部署与限流都还没做。
3. **提醒不会真正触发。** 只有间隔设置与下次时间预览，没有本地通知调度。
4. **照片上传没有 EXIF 解析。** 拍摄时间取文件修改时间；压缩到最长边 1200 / JPEG 0.82。
5. **Live 不是系统级 Live Photo。** 浏览器拿不到 iOS 相册里「静态图 + 配对 MOV」的配对关系，因此 Live 需要选择导出的短片；网页会截取首帧作为封面。视频可播放性取决于浏览器编解码（Chrome 不支持 HEVC）。
6. **视频不进入 JSON 备份。** 导出只包含记录与海报索引，视频原片仍在本机 IndexedDB 中。
7. **仅中文界面。** 英文只出现在品牌词、眉标与字标中，尚未做 i18n。
8. **未做无障碍与低端设备专项审计。** 已有 `prefers-reduced-motion`、焦点样式与 aria-label，但未跑完整 axe 检查。
